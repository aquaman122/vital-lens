# kt-market 페이지별 종합 분석 (2026-08-27)

> 근거: vital-lens 실사용자 측정(release `framer-0827`, 8/27 부착 후) + GA4(8/26 세션) + Clarity(8/26 행동).
> 표본이 하루치라 수치는 변할 수 있다 — 단, 아래 "구조적 발견"은 표본이 늘어도 바뀌지 않는 종류의 문제다.

## 한 줄 요약

**사이트 전체는 건강하다(LCP p75 1.5초, 좋음). 그러나 상품 상세 페이지 전부가 같은 이유로 느리고(제품 이미지 발견 지연), 그건 템플릿 한 곳만 고치면 한꺼번에 풀린다.**

---

## 구조적 발견 — 개별 페이지 문제가 아니다

`/phone/*` 상세 페이지 **전부**에서 LCP 요소가 동일한 패턴이다:

| path | LCP p75 | 발견 지연 | 다운로드 |
|---|---|---|---|
| /phone/sm-f971nk512 | 7,992ms | **6,869ms** | 122ms |
| /phone/sm-f976nk512 | 4,141ms | **3,322ms** | 74ms |
| /phone/aip17e-256 | 2,076ms | **2,601ms** | 0ms |
| /phone/aip17p-256 | 2,197ms | **1,722ms** | 292ms |
| /phone/sm-s942nk | 1,840ms | **1,703ms** | 0ms |
| /phone/sm-f971nk | 1,341ms | **1,172ms** | 0ms |

LCP 요소는 전부 S3의 제품 첫 이미지(`.../01.png`)다. **다운로드는 빠른데(수십~수백 ms, 캐시되면 0) 브라우저가 그 이미지를 발견하는 데 1~7초를 쓴다.** 이미지가 무겁지 않다 — 늦게 요청될 뿐이다. 원인은 상품 상세 템플릿에서 이미지가 JS 렌더 이후에야 DOM에 등장하는 구조.

**액션 (1건, 전 상품 페이지 동시 개선)**: Framer 상품 상세 템플릿에서 첫 제품 이미지에 우선순위를 줘라 — Framer 이미지 설정에서 해당 이미지 lazy load 해제(eager), 가능하면 페이지 Custom Code `<head>`에 preload 힌트. 이거 하나가 `/phone/*` 수십 페이지의 LCP를 동시에 줄인다.

## 페이지별 진단

### 1. `/event/foldable8` — 트래픽 1위, 상태 양호, 에러만 확인
- **규모**: 세션 2,902(GA4, 전체의 45%), LCP 표본 281건 — 이 사이트의 얼굴.
- **성능**: LCP p75 1,604ms, 단계도 고름(발견 291/다운로드 316/렌더 168). 표본이 쌓이면서 초기에 보이던 3.4초 히어로 문제는 상위 케이스였던 것으로 정리됨. **지금은 손댈 것 없다.**
- **행동**: rage/dead click 0 — 사용자 불만 신호 없음.
- **에러**: `SyntaxError: Unexpected end of input` 2건 — 이 페이지의 스크립트 어딘가가 잘려 온다. 트래픽 1위 페이지라 방치 금물. **Framer Custom Code(페이지 단위)에 미완성 스크립트가 있는지 확인해라.**

### 2. `/phone/sm-f971nk` (갤럭시 폴드7?) — 행동 문제 1위
- **규모**: 세션 303 — 상품 페이지 중 최다.
- **성능**: LCP 1,341ms 양호 (발견 지연 1,172ms — 위 구조적 수정에 포함됨).
- **행동**: **dead click 129회 + rage 7회 + quickback 14회 — 사이트 전체 행동 문제의 최다 지점.** 눌리는 것처럼 생겼는데 반응 없는 요소가 있다. 숫자로는 어느 요소인지 알 수 없다 — **Clarity에서 이 페이지 레코딩 3~4개를 재생하면 5분 안에 나온다.** 스펙 표, 색상 선택, 비활성 버튼이 흔한 범인.
- 파생형 `/phone/sm-f971nk512`(512GB)는 LCP 7,992ms로 최악이지만 표본 1건 — 결론 보류, 구조적 수정에 어차피 포함된다.

### 3. `/phone/aip17p-256` (아이폰17 프로) — 성능+행동 복합
- **규모**: 세션 112.
- **성능**: LCP 2,197ms, 발견 지연 1,722ms — 구조적 수정 대상.
- **행동**: dead click 65회 + quickback 11회. 세션 대비 비율로 보면 sm-f971nk보다 높을 수 있다. 마찬가지로 **레코딩 확인 대상.**

### 4. `/event/internet` — 느린데 아직 표본 부족
- LCP 3,094ms(표본 8), 발견 지연 1,911ms — 이벤트 배너 이미지가 상품 페이지와 같은 패턴. 세션 47. 트래픽이 작아 우선순위는 낮지만, 이벤트를 밀기 시작하면 트래픽이 몰릴 페이지 — **캠페인 전에 고쳐두는 게 맞다.**

### 5. `/event/galaxy-26` — 유일하게 "다운로드가 느린" 케이스
- 발견 지연 16ms인데 **다운로드 818ms** — 다른 페이지와 반대로 이미지 자체가 무겁다(`s26-event-main-banner.png`). PNG를 webp로 바꾸고 압축하면 끝. 세션 61.
